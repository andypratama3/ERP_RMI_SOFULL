SOP Master Data ERP_RMI_SOFULL

Dokumen operasional master data untuk Admin/ITC/Owner - versi 2026-02-11

Tujuan: memastikan pengelolaan master data berjalan konsisten, aman, dan auditable untuk semua modul transaksi ERP.

Ruang Lingkup

SOP ini berlaku untuk menu pada master/index.php dan halaman master terkait:

  • master/master_products.php
  • master/master_customers.php
  • master/master_vendors.php
  • master/master_office.php
  • master/master_departements.php
  • master/master_system_login.php
  • master/account_readiness.php
  • master/master_tax.php
  • master/master_payment_terms.php
  • master/master_pricelist.php dan master/master_pricelist_sell.php
  • master/company_bank_accounts.php

Prasyarat Akses

  • Operator wajib login.
  • Perubahan master data hanya oleh role berwenang sesuai guard halaman.
  • Semua mutasi dilakukan via POST + CSRF valid.

SOP Inti (Wajib)

1) Validasi sebelum perubahan

  1. Pastikan data yang akan diubah benar (kode, nama, office, status).
  2. Cek potensi duplikasi data di tabel list/search.
  3. Untuk data berisiko tinggi (office code, tax, bank account), lakukan verifikasi dua pihak.

2) Eksekusi perubahan

  1. Lakukan tambah/edit/nonaktif sesuai kebutuhan bisnis.
  2. Hindari delete permanen bila data sudah terpakai transaksi; gunakan inactive jika memungkinkan.
  3. Simpan perubahan dan pastikan notifikasi sukses muncul.

3) Verifikasi dampak

  1. Uji minimal 1 alur transaksi terkait (contoh: Sales/PO/DO).
  2. Pastikan referensi master muncul benar di dropdown/lookup lintas modul.
  3. Jika ada ketidaksesuaian runtime, cek tools/review_kit_workspace.php?mode=single dan tools/readiness_audit.php.

4) Audit dan kontrol

  1. Pantau audit gabungan di tools/review_kit_workspace.php (Unified Module Audit Log).
  2. Untuk akun login, audit detail ada di uploads/audit_logs/audit_master_system_login.log.
  3. Simpan bukti perubahan penting (tanggal, operator, alasan perubahan).

SOP Khusus per Domain Master

Office & Departements: jaga konsistensi kode referensi lintas modul, import hanya template resmi, dan cek dampak geofence ke Absensi.

System Login & Readiness: akun ACTIVE wajib punya department + office_code; gunakan master/account_readiness.php untuk remediation.

Produk/Customer/Vendor: hindari hapus data yang sudah dipakai transaksi; utamakan nonaktif.

Keuangan Master: perubahan tax/term/pricelist/bank account mengikuti DoA/SoD dan wajib uji dampak transaksi.

Checklist Harian Admin Master Data

  1. Cek issue readiness akun di master/account_readiness.php.
  2. Cek anomali audit di tools/review_kit_workspace.php.
  3. Cek konsistensi office/dept/master referensi utama.
  4. Pastikan tidak ada perubahan master kritikal tanpa approval.

Eskalasi

  • Mismatch frontend/backend: cek source data, migration source, dan runtime DB.
  • Temuan keamanan/akses: eskalasi ke Security/ITC dan hold mutasi bila perlu.
  • Temuan audit kritikal: hentikan perubahan lanjutan sampai root cause ditemukan.
